# ADR-002: 环境隔离与宿主 GPU 驱动透传策略

## 状态
已采纳 (Accepted) - 2026-09-18；2026-09-30 补充实际隔离范围。

## 背景
AI 桌面应用若直接使用 `pip install` 向用户系统全局环境写入包，极易引发依赖地狱并污染用户个人环境；但若强制重新安装 CUDA Toolkit 又会造成重复下载与巨大浪费。

## 决策
源码使用 `uv` 管理项目 `.venv`；Windows 便携版使用自带 `runtime`。Torch 通过操作系统提供的 NVIDIA 驱动或 Metal 使用硬件，模型按 Torch 的实际能力选择设备。

## 理由
1. 不向宿主全局 Python 安装包。Windows 算力包在项目独立目录准备并于重启后激活，避免覆盖已加载的 DLL。
2. CUDA wheel 与宿主 NVIDIA 驱动配合使用；CUDA/MPS 的真机兼容性须单独验证。
3. 自动选择可用设备，无加速设备时使用 CPU；用户强制指定不可用设备时返回明确错误。

这里的隔离针对依赖和应用数据，不是操作系统权限沙盒。uv 管理的 Python、浏览器与第三方库可能使用系统缓存；不承诺删除一个目录即可清除所有残留。
